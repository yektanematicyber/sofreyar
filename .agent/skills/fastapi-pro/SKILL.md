# FastAPI Pro: Safreyar Backend Engineering Guide

This skill provides expert-level guidance, patterns, and best practices for developing, refactoring, and maintaining FastAPI services in `safreyar-backend`.

## 1. Project Standards & Versions

* **FastAPI:** `>=0.115.0` (using Starlette and ASGI lifespan architecture)
* **Pydantic:** `2.x` (using `@field_validator`, `@model_validator(mode='after')`, `BaseModel`, `EmailStr`)
* **Python Runtime:** `3.12+` (native union syntax `X | Y`, generic built-ins `list[T]`, `dict[K, V]`)
* **Base URL:** Port `8001` (Docker: `http://localhost:8001`, Local: `http://127.0.0.1:8001`)

## 2. Router & Route Organization

All routes must be modularized into dedicated routers under `app/routers/` and registered with clean prefixes and tags in `app/main.py`.

### Router Conventions:
```python
from fastapi import APIRouter, Depends, HTTPException, Query, status
from sqlalchemy.orm import Session

from app.database import get_db
from app.dependencies import get_current_user
from app.models.user import User
from app.schemas.example import ExampleCreate, ExampleOut

router = APIRouter(prefix="/examples", tags=["Examples"])
```

### Async vs Synchronous Route Functions:
* **Synchronous Endpoints (`def`):** When performing blocking operations such as standard SQLAlchemy ORM queries with `Session` (`psycopg2-binary`), declare route functions with `def`. FastAPI runs synchronous route functions in a separate threadpool (`anyio.to_thread.run_sync`), preventing blocking of the main ASGI event loop.
* **Asynchronous Endpoints (`async def`):** Use `async def` ONLY when awaiting non-blocking asynchronous operations (such as `httpx.AsyncClient`, `asyncio.sleep`, or async database drivers like `asyncpg`).

## 3. Pydantic V2 Data Validation Standards

In `safreyar-backend`, all input payloads and response models must follow Pydantic V2 idioms:

### Best Practices:
1. **Model Configuration:** Always set `model_config = {"from_attributes": True}` on output schemas that serialize SQLAlchemy ORM models.
2. **String Sanitization:** Clean whitespace and normalize inputs using `@field_validator` with `@classmethod`:
   ```python
   @field_validator("name")
   @classmethod
   def normalize_name(cls, value: str) -> str:
       value = " ".join(value.split())
       if not value:
           raise ValueError("Name cannot be empty")
       return value
   ```
3. **Email Handling:** Use `EmailStr` and normalize to lowercase before database persistence.
4. **Dates & Timestamps:** Always serialize dates in ISO-8601 format (`YYYY-MM-DD` or `YYYY-MM-DDTHH:MM:SSZ`).
5. **Partial Updates (PATCH):** Use `Optional[T] = None` on update schemas and extract dirty fields using `.model_dump(exclude_unset=True)`:
   ```python
   update_data = payload.model_dump(exclude_unset=True)
   for field, value in update_data.items():
       setattr(db_item, field, value)
   ```

## 5. Standard Error Handling & Status Codes

Adhere strictly to the `API_CONTRACT.md` status codes:
* `200 OK`: Successful retrieval or modification.
* `201 Created`: Successful resource creation (e.g., `/auth/register`, `/pantry`).
* `204 No Content`: Successful deletion without response body (e.g., `DELETE /pantry/{item_id}`).
* `400 Bad Request`: Malformed business logic request.
* `401 Unauthorized`: Missing or invalid JWT bearer token.
* `403 Forbidden`: Authenticated user does not have permission for the resource.
* `404 Not Found`: Resource does not exist.
* `409 Conflict`: Unique constraint violation (e.g., duplicate email registration).
* `422 Unprocessable Entity`: Schema validation errors (automatically generated by Pydantic/FastAPI).
